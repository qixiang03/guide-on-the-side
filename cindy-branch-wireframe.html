Cindy's Design: How It Worked (729a718)

Flow: Student answers incorrectly → attemptCounts[stepIndex]++ → once attempts ≥ branch_trigger_attempts → shouldTriggerBranch() returns true → showBranchPrompt(stepIndex) opens the modal overlay

Modal approach: The branch is a full-screen modal overlay on top of the existing split-screen. It does NOT change the step index or progress bar. The student is still conceptually "on Step 3" — they're just viewing remediation content in an overlay.

Mandatory vs. Optional:

• Mandatory: Next button stays locked until completedBranchSteps.has(i) is true AND the quiz is passed. No Skip or Close button.

• Optional: Student can Skip or close the modal (×) and retry the quiz. Close button visible.

Key JS state variables:

• triggeredBranchSteps (Set) — which steps have shown the branch modal

• completedBranchSteps (Set) — which steps the student has completed the branch for

• activeBranchStep — currently active branch step index (or null)

• branchReturnTarget — step index to return to after branch

What was in the template: A hidden #pbsgBranchModal div with backdrop, dialog, title, text area, and action buttons (Start / Skip / Complete / Return / Close). Controlled entirely by JS show/hide.
